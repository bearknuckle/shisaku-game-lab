## 1. 開発方針

本作は、KONAMI「FIELD OF NINE」のゲーム構造を研究し、動物選手・独自カード・独自画面で再構成するブラウザゲームとする。

重要な原則：

1. 2000年版カードゲーム（TCG）と2001年GBA版を別々のルールセットとして調査する。
2. 両者が同一ルールであると確認できるまでは、同一視しない。
3. 公式資料・実物カード・実機プレイで確認できた事項と、二次資料の記述、推測、未確認事項を分離する。
4. 元作品のカード画像・カード文章・実在選手のデータをそのまま転載しない。ゲーム構造を参考にし、動物キャラクターと数値・カード文面は独自制作する。
5. ルールが未確認の箇所は実装で埋めず、「未確定」として残す。

## 3. 現時点の確認事項

以下は現行試作ページと公開されている二次資料から把握できる範囲であり、すべてが公式一次資料で確定したわけではない。

| 項目 | 現時点の把握 | 扱い |
|---|---|---|
| 選手カード | 選手ごとの能力値・ランク・個別判定表・特殊能力が存在するという情報 | 二次資料との照合が必要 |
| 作戦カード | 安打・本塁打・バント・盗塁などの作戦系カードが存在するという情報 | カード実物・攻略本で照合 |
| 特殊能力 | 打順、走者状況、イニング、カードランクなどを条件とするものがあるという情報 | 個別カードごとに照合 |
| GBA版の基本構造 | ドロー、作戦、メイン、作戦実行、判定に相当する進行が紹介されている | 二次資料由来。実機映像で検証 |
| 攻守判定 | 攻撃側・守備側の能力値や作戦によって打席結果を決めるという紹介 | 判定表・数値境界は未確認 |

## 5. 実装段階の方針

### Phase 0：ルールの証拠集め
攻略本、カード実物、説明書、GBA実機プレイ動画を照合する。ルール項目ごとに根拠・出典・確度を記録する。

### Phase 1：ルールエンジンの設計
ルールが確定した項目のみ、次の独立モジュールとして設計する。
- 試合状態（イニング、表裏、アウト、走者、得点）
- デッキ・手札・ドロー
- 打順・選手能力
- 作戦選択・公開・解決
- 攻守判定
- 走者進塁・得点
- 特殊能力
- 攻守交代・試合終了

未確定の処理は仮実装せず、テスト用の差し替え可能なルールデータとして分離する。

### Phase 2：1打席の検証
カード選択から判定・走者処理までを、確認済みルールだけで再現する。テストケースを用意し、結果をログで追えるようにする。

### Phase 3：1イニングの試作
複数打席、アウトカウント、走者、得点、攻守交代を接続する。

### Phase 4：1試合・CPU・デッキ構築
試合終了条件、CPU、チーム編成、デッキ構築を段階的に実装する。

## 6. 現行試作ページの扱い

現行のチーム編成・カード図鑑・攻守差分計算は、画面と操作のプロトタイプとして残す。
ただし、現行の選手名・能力値・カード名・計算結果はすべて仮データであり、公式FIELD OF NINEの実データ・確定ルールとして扱わない。

正式な判定方式が確認できた段階で、仮データを独自の動物選手データへ置き換える。既存UIの表示が誤解を招く場合は「仮データ」「未確定」の注記を維持・強化する。
