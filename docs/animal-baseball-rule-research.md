## 1. 開発方針

本作は、KONAMI「FIELD OF NINE」のゲーム構造を研究し、動物選手・独自カード・独自画面で再構成するブラウザゲームとする。

重要な原則：

1. 2000年版カードゲーム（TCG）と2001年GBA版を別々のルールセットとして調査する。
2. 両者が同一ルールであると確認できるまでは、同一視しない。
3. 公式資料・実物カード・実機プレイで確認できた事項と、二次資料の記述、推測、未確認事項を分離する。
4. 元作品のカード画像・カード文章・実在選手のデータをそのまま転載しない。ゲーム構造を参考にし、動物キャラクターと数値・カード文面は独自制作する。
5. ルールが未確認の箇所は実装で埋めず、「未確定」として残す。

## 3.1 追加調査：カードのデータ構造（2026-11-25）

### Wikiの選手カード一覧から読み取れる項目（二次資料）

非公式Wikiの球団別カード一覧には、少なくとも次の列が掲載されている。

- カード番号
- 登録名
- ランク
- 攻撃値
- 守備値
- バッティング表（差分 -4 から +4 の列）
- 特殊効果
- 備考

参考例：西武ライオンズの選手カード一覧  
https://wikiwiki.jp/fo9/西武ライオンズ

この表形式から、選手カードは単純な「攻撃値と守備値の差」だけで共通の打撃結果を決めるのではなく、カードごとのバッティング表を参照する設計である可能性が高い。ただし、差分を作る正確な計算順、どちらからどちらを引くか、作戦カードや特殊効果をいつ加算するか、同値処理は未確認。現段階で式を確定実装しない。

### 特殊効果の条件例（二次資料）

Wikiの特殊効果一覧には、以下のような条件型の能力が掲載されている。

- 打順条件：一番打者・二番打者・三番打者
- 走者条件：ランナーなし、二塁・三塁、満塁など
- イニング・点差条件：終盤、リード中、ビハインド中など
- 選手ランク条件：手札から出すカードのランクに応じた攻撃・守備補正
- 作戦カード条件：バントC、安打C、本塁打Cなどの使用を条件に発動
- 守備・走塁条件：盗塁阻止、タッチアップ阻止、外野守備時の結果変更など

出典：https://wikiwiki.jp/fo9/特殊効果

これらは能力データの分類に役立つが、Wiki記述だけで全カード・全バージョンに共通する正式ルールと断定しない。2000年版・2001年版・付録カードの差異をカード単位で照合する。

### 作戦カードの種類の例（二次資料）

球団別一覧に掲載された作戦カードには、安打C、本塁打C、打点C、勝利C、勝率C、バントC、盗塁C、盗塁阻止C、監督C、月間MVP C、ベストナインCなどがある。

参考：
- https://wikiwiki.jp/fo9/ヤクルトスワローズ
- https://wikiwiki.jp/fo9/大阪近鉄バファローズ

カード名・種類の全体リスト、攻守どちらが使えるか、消費・再利用条件は未確認。名称だけを根拠に効果を推測しない。

### デッキ構成・大会ルールに関するコミュニティ投稿

Wiki掲示板には、50枚デッキ、Sランク枠10枚制限、DHありのスタメン、5イニング制大会などの実プレイヤー投稿がある。

出典：https://wikiwiki.jp/fo9/交流・情報交換掲示板

ただし、投稿者の使用デッキや大会ローカルルールを含むため、公式の標準ルールと混同しない。50枚・S枠10枚・5イニングを本作の仕様として採用するには、攻略本やルール説明書で別途確認する。

### GBA版のフェーズ情報の扱い

二次資料には「ドロー → 作戦 → メイン → 作戦実行 → 判定」に相当する5段階の進行が紹介されている。

出典：https://consoledictionary.com/games/18989

これはGBA版の調査仮説として記録する。画面・説明書・実プレイで各フェーズの名称と操作を確認するまでは、TCGのルールや本作の確定仕様には採用しない。

## 5. 実装段階の方針

### Phase 0：ルールの証拠集め
攻略本、カード実物、説明書、GBA実機プレイ動画を照合する。ルール項目ごとに根拠・出典・確度を記録する。

### Phase 1：ルールエンジンの設計
ルールが確定した項目のみ、次の独立モジュールとして設計する。
- 試合状態（イニング、表裏、アウト、走者、得点）
- デッキ・手札・ドロー
- 打順・選手能力
- 作戦選択・公開・解決
- 攻守判定
- 走者進塁・得点
- 特殊能力
- 攻守交代・試合終了

未確定の処理は仮実装せず、テスト用の差し替え可能なルールデータとして分離する。

### Phase 2：1打席の検証
カード選択から判定・走者処理までを、確認済みルールだけで再現する。テストケースを用意し、結果をログで追えるようにする。

### Phase 3：1イニングの試作
複数打席、アウトカウント、走者、得点、攻守交代を接続する。

### Phase 4：1試合・CPU・デッキ構築
試合終了条件、CPU、チーム編成、デッキ構築を段階的に実装する。

## 6. 現行試作ページの扱い

現行のチーム編成・カード図鑑・攻守差分計算は、画面と操作のプロトタイプとして残す。
ただし、現行の選手名・能力値・カード名・計算結果はすべて仮データであり、公式FIELD OF NINEの実データ・確定ルールとして扱わない。

正式な判定方式が確認できた段階で、仮データを独自の動物選手データへ置き換える。既存UIの表示が誤解を招く場合は「仮データ」「未確定」の注記を維持・強化する。
